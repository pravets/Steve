# Требования: мозги, зрение, инвентарь и сбор ресурсов (прожарено через grill-me)

**Дата:** 2026-08-15
**Ветка:** master
**Статус:** требования согласованы, реализация по этапам

## Проблемы (факты из кода)

1. `MineBlockAction` копает туннель по направлению взгляда игрока, не проверяя,
   есть ли цель рядом. «Дай oak log» → бот роет туннель под землёй.
2. `GatherResourceAction` — заглушка («Resource gathering not yet fully implemented»).
3. Дропы падают на землю (`destroyBlock(pos, true)`), инвентаря у бота нет.
4. `WorldKnowledge` сканирует радиус 16 с шагом 2, агрегирует топ-5 блоков по
   количеству без расстояний и направлений → промпт LLM получает шум
   («земля, камень, земля»), экшены скан не используют.

## Согласованные требования

### 1. Зрение (восприятие мира) — «честное», без читов
- Радиус скана настраивается в конфиге, **дефолт 32**
- **Никакого x-ray**: блок считается видимым только при наличии линии видимости
  (raycast от глаз бота до цели, без непрозрачных блоков между)
- Скан по требованию (когда нужно действие), кэш результата (~20 тиков)
- Целевой поиск «где находится блок X» (ближайшие позиции + расстояние)
- Сводка «что видно интересного»: деревья, руды, мобы, игроки, сундуки —
  с расстояниями и направлениями
- До 10 ботов одновременно без просадки сервера

### 2. Умный сбор ресурсов
- Стратегия по типу цели:
  - поверхностные (деревья, растения) → поиск видимой цели в открытом мире, полёт к ней, ломка
  - руды → поиск видимой руды (обрывы, пещеры, вскрытое туннелем), иначе копать туннель/шахту
- **Цель не найдена рядом → расширять поиск** (уйти дальше); туннель — только
  fallback для руд, для деревьев никогда
- Выдавать инструмент по типу: топор для дерева, кирка для камня/руды
- **Количество = предметы в инвентаре** (не сломанные блоки)
- **Полный инвентарь → телепорт к игроку, передача накопленного, возврат
  телепортом на рабочую точку, продолжение задания**
- На сервере без игрока: склад в сундуки в определённой области
  (уточняется: дефолт — ближайший сундук в радиусе 16 от рабочей точки;
  нет сундука → оставить на земле и доложить)

### 3. Инвентарь
- Честный лимит слотов **как у игрока (36)**, NBT-сохранение
- Дропы зачисляются напрямую при ломании + периодический подбор ItemEntity рядом
- Просмотр: **и панель K, и `/steve inventory <имя>`**
- Апгрейд (рюкзаки и т.п.) — в будущем, не сейчас

### 4. Отдача ресурсов
- Действие `give`: **оба режима**
  - авто: по завершении задания бот приносит всё накопленное
  - по команде: «give me the iron», «отдай всё»
- **Отдавать всё накопленное** (не выборочно)
- Передача: в инвентарь игрока, остаток — рядом на земле
- Телепорт к игроку для передачи допустим (это транспорт, не чит)

### 5. Мозги (LLM) и диалог
- Новые действия в реестр/промпт: `give`, `respond` (текстовый ответ),
  `look` (осмотреться и доложить)
- Промпт обогащается: инвентарь, инструмент, «я вижу: ...» с расстояниями
- **Бот отвечает текстом** («что ты видишь?» → описание через `respond`,
  сообщение в чат от имени бота — sendChatMessage уже есть)
- Fallback-паттерны дополнить под новые действия

## Этапы реализации

| Этап | Содержание | Ключевые файлы |
|------|-----------|----------------|
| **1. Зрение** | Честный скан (raycast), целевой поиск, кэш, радиус в конфиге, сводка для промпта | WorldKnowledge, SteveConfig, PromptBuilder |
| **2. Инвентарь** | 36 слотов + NBT, зачисление дропов, подбор ItemEntity, панель K + `/steve inventory` | SteveEntity, SteveGUI, SteveCommands, новое Inventory |
| **3. Умный сбор** | Стратегия поверхность/руда, расширение поиска, инструменты, счёт по предметам, авто-возврат при полном инвентаре | MineBlockAction, GatherResourceAction, новое HarvestAction |
| **4. Передача** | `give` (авто + команда), передача игроку, склад в сундуки | GiveAction, TaskPlanner (валидация), PromptBuilder |
| **5. Мозги/диалог** | `respond`, `look`, обогащённый промпт, fallback-паттерны | PromptBuilder, ResponseParser, LLMFallbackHandler |
| **6. Полировка** | Кэш/производительность (10 ботов), тесты на Forge-сервере, `/steve debug` расширить | — |

Каждый этап — отдельный коммит, после 3-го и 5-го — проверка на живом сервере.
